01 — The Product

What We're Building

SmartSales AI is a sales automation platform that lets any business run a 24/7 AI sales agent on WhatsApp — no human needed to respond to product questions, pricing, or orders.

Core Problem
Nigerian SMEs lose sales overnight
Most businesses miss 60–80% of WhatsApp inquiries that come in outside business hours. Customers ask "how much?", get silence, and buy from a competitor. SmartSales fixes this by putting an AI agent on every WhatsApp conversation, 24/7.
Our Solution
AI agent that knows your products
Business owners paste their price list and FAQs into the Settings page. Our AI (powered by Google Gemini) reads this knowledge base and answers customer questions, handles pricing, and nudges toward a purchase — all in a conversational WhatsApp style.
The Dashboard
Real-time CRM for sales teams
Agents get a live dashboard to monitor all conversations, see AI replies as they happen, take over from the AI with one click (Human Takeover), track lead status, and view revenue analytics — updated in real-time via Socket.IO.
Business Model
SaaS with 3-tier pricing
Free tier for web-only chat, ₦25,000/month Growth plan for WhatsApp + Instagram + auto-follow-ups, and custom Business pricing for multi-agent teams. The knowledge base is the lock-in — once a client configures their product catalogue, switching costs are high.

04 — Backend Engineer Guide

Backend Deep-dive

The backend is a FastAPI app that runs everything on one port — REST, webhooks, and Socket.IO all share port 8000. Build in this order.

1. Foundation First
Start with config.py (Pydantic Settings reads .env), then database.py (async SQLAlchemy engine + context manager). Never call os.environ directly — always use the settings object.
config.py → settings object, imported everywhere
database.py → Base class, get_db() context manager
.env → never committed to git
2. Models + Migrations
4 SQLAlchemy models. Lead uses PostgreSQL ARRAY for intent_tags. Message has wa_message_id for deduplication. Run Alembic after all 4 models are complete — not one at a time.
Lead → phone unique, ARRAY intent_tags, status enum
Message → ForeignKey to lead, wa_message_id
Sale → Numeric(12,2) for amount, never float
BusinessSettings → knowledge_base as Text field
3. Webhook Handler
The most critical file. Always return 200 — even on errors. Meta retries on any non-200 response, which floods your server. Check human_mode flag in Redis before calling AI.
GET /webhook/whatsapp → echo hub.challenge
POST /webhook/whatsapp → full 5-step pipeline
KeyError/IndexError → silently pass, return 200
4. Main Entry Point
The uvicorn command must point to socket_app, not app. This ensures FastAPI and Socket.IO share the same port. CORS must allow the frontend URL — in production restrict to your exact domain, remove the wildcard "*".
uvicorn app.main:socket_app --port 8000
socket_app = socketio.ASGIApp(sio, other_asgi_app=app)
All routers mounted in main.py
5. Key Data Rules
These decisions affect the whole team — agree on them now.
UUID everywhere
All primary keys are PostgreSQL UUIDs, not integers. Frontend TypeScript types use string to represent UUIDs.
Deduplication is mandatory
Always check wa_message_id before inserting a Message. Meta re-delivers webhooks during network issues. No dedup = double replies.
Amounts as Numeric(12,2)
Never store money as float — floating point precision errors cause rounding bugs. Use PostgreSQL Numeric, return as Python float in API responses.
No shared in-memory state
With 2+ uvicorn workers, Python class instance variables are not shared. All shared state (context, flags) must live in Redis, not in class properties.
05 — AI Engineer Guide

The AI Pipeline

Every customer message triggers two Gemini calls — one for the reply, one for intent classification. Using two models cuts cost by ~70% vs using Pro for everything.

INPUT
Incoming WhatsApp message
phone, customer_name, message text, wa_message_id. The webhook extracts these from Meta's JSON payload.
CONTEXT
Load conversation history from Redis
ContextManager.get_history(lead_id) returns the last N turns as [{customer: "...", ai: "..."}] dicts. Capped at 10 turns for the Gemini call (last 20 stored).
GEMINI PRO
Generate reply — gemini-1.5-pro, temp 0.7
System prompt includes: AI persona name, business name, customer name, full knowledge base, and 9 strict rules (keep it short, Nigerian tone, no hallucination, human handoff phrase). History formatted as alternating user/model turns.
FLASH
Classify intent — gemini-1.5-flash, temp 0.0
Separate lightweight call. Returns exactly one word: Buying / Pricing / Support / Inquiry / Complaint. Flash is 5–10x cheaper than Pro for this simple task. Invalid response defaults to "Inquiry".
SAVE
Persist reply + update Redis context
AI reply saved to PostgreSQL messages table. ContextManager.add_turn() appends this exchange to Redis (trimmed to MAX_HISTORY_TURNS=20). Lead intent_tags array updated, status auto-upgraded if Buying intent detected.
SEND
Reply to WhatsApp + push to dashboard
WhatsAppService.send_text() posts to Meta Graph API. SocketManager.emit_new_message() pushes to all connected dashboard clients. Both happen concurrently.
The Knowledge Base
This is the most important field in the whole system. When the _get_knowledge_base() method (currently a stub returning "") is wired to the DB, the AI becomes genuinely useful for each client. Advise every client to include:
Full product catalogue with prices
Frequently asked questions
Return / refund policy
Delivery timelines and fees
Business contact and location info
Human Handoff Logic
When a customer says "I want to speak to a human" — the AI is instructed to reply with a specific phrase. The dashboard agent then clicks "Human Takeover" which calls the /handoff endpoint. From that point, the webhook skips AI and routes messages directly to the dashboard.
Redis key: human_mode:{lead_id} = "1"
Auto-expires after 1 hour if agent forgets
POST /api/messages/{id}/handoff toggles it
Agent sends replies via POST /agent-reply

Key Implementation Notes
📱
Mobile: Bottom Nav replaces Sidebar
On screens under 1100px, hide the 220px sidebar. Show a fixed bottom navigation bar with icon-only links. ChatWindow becomes full-screen overlay when a conversation is selected.
📊
Charts must use dynamic() with ssr: false
Recharts does not support server-side rendering. Every chart component must be imported using Next.js dynamic() with ssr: false, otherwise the build fails.
🔄
Socket.IO — one socket instance
The socket.ts file creates a singleton. getSocket() returns the existing connection — never create a new io() on every component render. Join lead rooms with emit('join_room', {lead_id}).
💰
All amounts in ₦ Nigerian Naira
Use Intl.NumberFormat with style: 'currency', currency: 'NGN' for formatting. The backend returns raw floats — format at the UI layer. Never hardcode currency symbols in backend code.
🎭
Avatars from DiceBear API
Use https://api.dicebear.com/7.x/initials/svg?seed={name} for all user avatars. No uploads required for MVP. Memoize Avatar components — they're rendered in long lists.
07 — API Contract

REST Endpoints Reference

The backend exposes these endpoints. The frontend consumes them. This is the official handoff boundary between the two teams — agree on this before building.

Method + URL Who Calls It What It Does
GET/health DevOps Health check — returns {"status": "ok"}
GET/webhook/whatsapp Meta (verification) Echo hub.challenge to verify the webhook URL
POST/webhook/whatsapp Meta (incoming messages) Full AI pipeline — receive, process, reply, push to dashboard
GET/api/leads/ Frontend (Leads page) All leads, newest first. Filter by ?channel= and ?status=
GET/api/leads/{id} Frontend (Conversation) Single lead by UUID
PATCH/api/leads/{id} Frontend (Edit lead) Update name, status, or reset unread_count
GET/api/messages/{lead_id} Frontend (ChatWindow) All messages for a conversation, chronological order
POST/api/messages/{lead_id}/agent-reply Frontend (ChatWindow input) Agent sends a manual message — saves to DB + sends to WhatsApp
POST/api/messages/{lead_id}/handoff Frontend (Human Takeover toggle) Body: {isHuman: true/false}. Sets/clears Redis human_mode flag
GET/api/analytics/dashboard-stats Frontend (Overview stats cards) Today's totals: chats, new leads, sales closed, revenue generated
GET/api/analytics/funnel Frontend (SalesFunnelWidget) Lead count per funnel stage with colors for charting
GET/api/settings/ Frontend (Settings page) Current business settings. Auto-creates default row on first run
PUT/api/settings/ Frontend (Settings save) Update business name, AI persona, tone, knowledge base, toggles

Socket.IO Events

join_room
Client → Server. Frontend emits this when a conversation is opened. Payload: {lead_id}. Only clients in the room receive that lead's events.
new_message
Server → Client. Emitted after every AI reply. Payload: leadId, customerMessage, aiReply, leadName, leadPhone. Triggers toast notification.
lead_updated
Server → Client. Emitted when a lead's status changes. Payload: leadId, status, name. Used to update the conversations list without a full refetch.

09 — Risks & Best Practices

What Can Go Wrong & How to Avoid It

These are the most common failure points on projects like this. Read them now, not after something breaks in production.

High Risk
Duplicate WhatsApp messages
Meta re-delivers webhooks on network errors. Without deduplication on wa_message_id, customers get double AI replies. The save_message() function must check this ID before inserting — always.
High Risk
Webhook returning non-200
If the webhook handler raises an unhandled exception and returns 500, Meta retries delivery for hours. Always wrap the entire POST handler in try/except and return {"status": "ok"} regardless.
High Risk
24-hour WhatsApp message window
Meta only allows free-form messages within 24h of the customer's last inbound message. Auto-follow-ups sent after this window will fail silently. Plan to use approved Message Templates for late follow-ups.
Medium
Gemini rate limits at scale
Gemini 1.5 Pro allows 360 requests/min on the free tier. With many concurrent conversations, add asyncio.Semaphore(50) to cap concurrent AI calls. Upgrade to a paid tier for production.
Medium
Recharts SSR crash
Recharts uses browser APIs not available in Node.js. Every chart component must use Next.js dynamic() import with ssr: false. Forgetting this causes a build error that's confusing to debug.
Medium
ngrok URL changes on restart
During development, ngrok generates a new URL every session (free plan). Each restart requires updating the Webhook URL in the Meta Developer Portal. Document this step for every team member.
Low
Temporary access token in production
The Meta Developer Portal issues a 24-hour access token by default. Before going live, generate a permanent System User token via Meta Business Suite. The 24h token silently expiring is easy to miss.
Low
Socket.IO wildcard CORS
The Socket.IO server is initialized with cors_allowed_origins="*" for development. Before deploying to production, restrict this to your exact frontend domain (settings.FRONTEND_URL). Wildcard CORS is a security risk.
Low
Shared state across workers
With 2 uvicorn workers, Python in-memory variables are not shared. All per-lead state (conversation context, human mode flags) must live in Redis. Never store this in class instance variables.
